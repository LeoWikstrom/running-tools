# running-tools monorepo

An npm workspace. Full plan for the audio guide in `docs/build-plan.md` — read it before
starting a new phase.

- `packages/core` — shared TypeScript, imported as `@running/core/<path>` (source-level
  exports, no build step): `geo`, `gpx/`, `graph/`, `net/`, `search/`, and (from phase 1)
  `poi/`, `text/`, `tour/`. Tests in `packages/core/test` (vitest, node env).
- `apps/profile-course` — RaceTwin, the race-profile course generator (display name only;
  dir and URL keep the old name — see its own CLAUDE.md). Its
  non-UI modules were moved into core in phase 0; only `src/main.ts`, `src/session.ts`,
  `src/ui/`, `src/shared/messages.ts` and `src/search/worker.ts` remain.
- `apps/runtour` — audio-guide preparation app (map, places, texts, tour.json). One codebase,
  two builds: the default run variant (accent green) and `--mode bus` → BusTour (blue, line
  picker instead of the generator, bus pace/trigger defaults in `src/variant.ts`). `npm run
  dev` serves run on 5173, `npm run dev:bus` bus on 5174; `npm run build` emits `dist/` and
  `dist-bus/` (deployed to `/runtour/` and `/bustour/`). Changes to the app apply to both
  variants — gate variant-specific UI with `.run-only`/`.bus-only` classes or `VARIANT`.
- `android/runtour` — (phase 3) plain Java, Gradle-free build modelled on
  `~/sylvester/sylvester/build.sh` (aapt2, javac, d8, apksigner); WebView loads the runtour
  build from assets.
- `site/` — static landing page for GitHub Pages. `.github/workflows/pages.yml` builds every
  `apps/*` on push to main and deploys each `dist` to `/<app>/`; a new app just needs a card
  in `site/index.html`, headlined Tours & Courses. The APKs (runtour, bustour, racetwin)
  are GitHub Release assets — `android/runtour/release.sh` builds and uploads all three.

Conventions: finish a phase → `npm test` and `npm run lint` from the root → commit with the
phase name → next phase. Dev servers bind 0.0.0.0 for phone testing in Termux.

Android: `android/runtour/build.sh` builds the signed APK (it builds the web app first;
`SKIP_WEB=1` skips that; `VARIANT=bus` builds bustour.apk — own app id via
--rename-manifest-package, dist-bus assets, blue icon — from the same sources).
`android/racetwin/build.sh` wraps apps/profile-course in a minimal WebView APK (no native
bridge; sw.js deliberately 404s — service-worker fetches bypass the asset interception).
`android/runtour/test.sh` replays the runtime golden traces
(`test/runtime-cases.txt`, regenerated by `packages/core/test/runtime.test.ts`) against
RunRuntime.java on the JVM. The trigger algorithm lives twice — `core/tour/runtime.ts` and
`RunRuntime.java` — change both or the replay fails.

Phases 0–6 are built; still to do from the plan: the phase 4 field test on a real run
(tune leadDistance and the trigger window), the first GitHub push (static deploy is prepared —
checklist in README.md), and phase 7 (LLM rewriting, cloud TTS, Garmin export).
